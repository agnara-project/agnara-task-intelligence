# Documentation Guidelines

This project requires high-quality, professional documentation.

## When to Update What
- **README.md**: Update if the core purpose, installation, or basic usage changes.
- **docs/architecture.md**: Update if the data flow or execution model changes (e.g., how the CLI interacts with the Agnara Runtime).
- **docs/capabilities.md**: Update if new capabilities are added, or if existing capabilities modify their inputs, outputs, scopes, or risks.
- **CHANGELOG.md**: Document any notable changes, keeping the historical nature of the project in mind.
- **docs/history.md**: Do not alter the historical baseline. This document preserves the exact conditions under which this project was created.

Ensure that the distinction between "Capability Risk" (operational risk) and "Task Risk" (domain logic output) is clearly documented.
